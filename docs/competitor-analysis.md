## 1. 执行摘要与调研背景

在数字化知识管理（PKM）与高强度智力工作日益普及的今天，知识工作者面临着双重挑战：**一方面是严重的精力碎片化与虚假努力（忙碌一天却缺乏真实积累）**；**另一方面是传统时间打卡工具强烈的“心流打断感”（为了记时间而频繁暂停思考）**。

思源笔记（SiYuan）作为基于块级（Block-level）和本地优先（Local-First）架构的现代化双链笔记系统，拥有大量从事考研考公、学术科研、长文写作与专业技术攻关的深度用户。由开发者打造的**“源时记”（siyuan-time-spent）**插件在 `v0.8.0` 版本中推出了全自动文档时间追踪、智能离桌去水防挂机、日/周/月全景看板与 AI 深度复盘等核心功能，初步形成了“静默采集 - 多维透视 - 闭环沉淀”的产品雏形。

为了进一步明确产品在同类生产力工具中的竞争格局，找准差异化优势与功能短板，本报告展开了全方位的横向竞品调研：
1. **纵深剖析 Obsidian 社区的主流解决方案**（如 `Vault Time Tracker`、`Pomodoro Timer`、`Time Ruler` 等）；
2. **横向对标桌面端顶级原生应用**（如 `Rize.io`、`Timing (macOS)`、`ActivityWatch` 等）；
3. **考察移动端自律与专注工具**（如 `Session`、`Forest`、`OffScreen` 等）。

通过对比分析，“源时记”在**思源生态咬合度、可视化美学看板、本地隐私优先、AI 复盘与思源文档一键沉淀**上表现亮眼，但仍在**“主动专注（番茄钟）缺失”、“移动端适配空白”、“产出量化（字数/编辑）脱钩”、“统计层级单薄”**等方面存在待补齐的关键短板。本报告旨在为后续版本演进提供科学、详尽的产品与技术路线指南。

## 2. 产品定位、使用场景与目标用户群深度画像

### 2.1 产品定位与核心主张

- **产品定位**：思源笔记生态首款**“深度工作（Deep Work）效能底座”**与**“无感时间流画像看板”**。
- **品牌口号**：量化时间痕迹，助你高效复盘。
- **核心主张 (Value Proposition)**：
  - **零负担无感采集**：让时间记录成为像呼吸一样的底层基础设施，坚决杜绝打断用户沉浸思考；
  - **客观去水真实量化**：以毫秒级外设交互为依据剥离离桌挂机，还原真实的智力投入，杜绝“自我感动”；
  - **一体化生态闭环**：不脱离思源笔记独立运行，实现“看板看数据 $\rightarrow$ 点击跳文档 $\rightarrow$ AI 提炼反思 $\rightarrow$ 一键归档进笔记”的完整生产力闭环。

### 2.3 典型使用场景与价值闭环

1. **场景一：日常静默无感伴随（工作/学习中）**
   - 用户打开思源笔记，开始阅读或编辑考点笔记。插件通过 [`TimeTracker`](file:///d:/MyCodingProjects/siyuan-time-spent/src/utils/tracker.ts) 毫秒级静默启动计时；
   - 用户起身去倒水或讨论问题（超过 5 分钟无鼠标键盘交互），[`IdleWatcher`](file:///d:/MyCodingProjects/siyuan-time-spent/src/utils/idle-watcher.ts) 精准识别并将该时间段扣除；
   - 用户返回敲击键盘，计时无缝恢复，全程**零弹窗、零提示音、零操作成本**。
2. **场景二：睡前或每日收尾微复盘（傍晚/夜间）**
   - 用户点击思源顶栏“源时记”图标，打开日视图看板；
   - 看到 24 小时纵向时间轴（Time-blocking），清楚直观地看到上午 9:00-11:30 专注在《专业课错题》，下午 14:00-16:00 投入在《论文引言》，净专注 5 小时 42 分钟，闲置剔除 48 分钟；
   - 达成今日设定目标，获得扎实笃定的成就感，告别“虚度一天”的焦虑。
3. **场景三：周末/月末深度周期反思（周日晚/月末）**
   - 用户切换至周视图或月视图，查看整周文档分布环形图与整月日历热力图；
   - 点击右上角「AI 总结」，配置的大语言模型自动流式输出结构化诊断报告（包含目标达成评估、碎片化诊断与 3 条针对性改进动作）；
   - 用户点击「保存为思源文档」，报告一键生成为知识库中的独立日记或复盘笔记，实现完整生产力闭环。

## 3. 竞品横向深度调研与行业标杆拆解

为了建立立体的行业参照系，本次调研覆盖了三大阵营：**Obsidian 生态插件**、**PC 桌面原生自动化追踪工具**、**移动端原生专注应用**。

### 3.1 阵营一：Obsidian 社区同类与衍生插件生态

Obsidian 作为同为 Markdown 语法的双链笔记代表，其社区积累了多种时间管理类插件，其模式极具参考价值：

```
┌────────────────────────────────────────────────────────────────────────┐
│                        Obsidian 社区同类插件生态图谱                     │
├──────────────────────────┬─────────────────────────────────────────────┤
│ 类别                     │ 代表插件与核心模式                          │
├──────────────────────────┼─────────────────────────────────────────────┤
│ 1. 自动无感文档计时     │ Vault Time Tracker (自动监听文档切换+闲置暂停)│
├──────────────────────────┼─────────────────────────────────────────────┤
│ 2. 番茄钟与主动专注     │ Pomodoro Timer / Gentle Pomodoro (状态栏番茄)│
├──────────────────────────┼─────────────────────────────────────────────┤
│ 3. 任务驱动与行内打卡   │ Task Time Tracker (绑定 Markdown Checkbox)   │
├──────────────────────────┼─────────────────────────────────────────────┤
│ 4. 可视化时间块与热力   │ Time Ruler / Timegrain (时间轴、能量感知)   │
├──────────────────────────┼─────────────────────────────────────────────┤
│ 5. 跨应用无感聚合       │ obsidian-activitywatch (借力外部监控引擎)    │
└──────────────────────────┴─────────────────────────────────────────────┘
```

#### 1. Vault Time Tracker
- **核心机制**：监听当前激活的文件变更事件，自动统计每个 Markdown 文档的累计阅读与编辑时长；提供侧边栏小面板与全屏看板；内置了基础的 Idle 闲置检测。
- **优点**：理念与“源时记”最接近，均为全自动文档级追踪；数据保存在 Vault 本地。
- **缺点**：
  - 看板设计较为简陋，缺乏符合现代美学的专业级图表与 24h 细颗粒度时间轴；
  - 闲置去水逻辑较为生硬，缺少对离桌时间的精细切片，无法追溯“哪一段是闲置”；
  - 缺乏 AI 智能化复盘能力，不支持与大模型结合进行深度工作习惯诊断。

#### 2. Pomodoro Timer & Gentle Pomodoro
- **核心机制**：标准的番茄工作法（25 分钟工作 + 5 分钟休息），通常寄生在状态栏（Status Bar）；支持将每一次番茄钟的起止时间、耗时和关联笔记写入笔记的 Frontmatter 或追加到 Daily Note。
- **优点**：
  - 主动性极强，对于需要克服拖延症、进行高强度冲刺的用户极度友好；
  - **与 Dataview 深度咬合**：由于数据沉淀为标准 YAML/Frontmatter，用户可以使用 Dataview 编写 SQL-like 语句自由构建任何报表。
- **缺点**：必须用户每次手动点击启动/暂停，一旦忘记打卡便中断；无法感知用户是否在番茄钟期间离开电脑发呆，极易产生“虚假番茄”。

#### 3. Task Time Tracker
- **核心机制**：在 Markdown 任务列表（`- [ ] 任务项`）旁增加行内微型播放/暂停按钮，点击即可直接为该特定任务打卡。
- **优点**：颗粒度极细，直接精准到具体事务项，特别适合项目制（Project-based）的自由职业者或开发者做工时统计。
- **缺点**：操作负担极重，用户每换一个子任务都需要手动打卡，心流打碎严重；完全不支持文档宏观维度的全天热力透视。

#### 4. Timegrain & Pomodoro Calendar
- **核心机制**：将时间追踪与“精力/情绪评分（Energy Awareness）”结合，专注结束后弹窗让用户评价当前疲劳度（1~5星），并在日历中展示情绪与效率的交叉热力图；支持双向同步 Google Calendar / CalDAV。
- **优点**：引入了心理学与精力管理模型，帮助用户找到个人“生物钟黄金时段”。
- **缺点**：打扰频次过高，每次专注结束后的打分机制在数周后容易让用户产生答题倦怠。

> **Obsidian 生态综合评述**：  
> Obsidian 生态呈现**“高度碎片化、拼接式”**特征。用户想要既有自动记录、又有番茄钟、又有看板、又能复盘，往往需要同时安装 3~4 个插件（如 `Vault Time Tracker` + `Pomodoro Timer` + `Dataview` + `Tracker`），配置门槛极高，UI 风格各异，割裂感强烈。“源时记”一体化的整装开箱即用体验形成了鲜明的体验断层领先。

### 4.4 当前核心差距与短板剖析 (Gap Analysis)

通过上述对比，精准定位出当前 `v0.8.0` 存在的**五大功能断点与体验盲区**：

1. **“只有被动底噪，缺乏主动冲刺”（缺少番茄钟与主动倒计时）**
   - *问题现状*：目前插件完全是被动追踪。但考研备考、刷题、攻坚长文时，用户极度需要“定一个 25 分钟倒计时强迫自己冲刺”的主动仪式感；
   - *用户后果*：备考用户仍需在手机或电脑另开一个番茄钟软件，导致精力割裂。
2. **“移动端（Mobile / Tablet）完全封锁”**
   - *问题现状*：[`plugin.json`](file:///d:/MyCodingProjects/siyuan-time-spent/plugin.json#L16-L20) 中 `frontends` 仅配置了 `desktop`, `browser-desktop`, `desktop-window`，直接排除了 `mobile`；
   - *用户后果*：大学生与备考党在图书馆使用 iPad / 安卓平板写思源、看文档时，完全无法使用插件，错失了 40% 以上的备考黄金场景。
3. **“纯时间度量，不等于实际生产力”（缺少与文字产出/编辑块数的关联）**
   - *问题现状*：用户打开一篇文档看 2 小时，可能真的在深度思考，也可能只是在轻度神游（微小晃动鼠标避开闲置检测）；
   - *行业对标*：长文写作软件（如 Scrivener、Word Sprint）均将**“专注时长”与“净增字数（WPM 写作速率）”**联动计算投入产出比。
4. **“统计粒度单一，缺乏多维透视与下钻”**
   - *问题现状*：当前聚合仅基于单篇 `docId`。在思源中，用户通常拥有多层笔记本（Notebook）、文档标签（Tags）与多级标题块（Headings）；
   - *用户诉求*：无法回答“本周我在《考研数学》整个笔记本上花了多少时间？”或者“所有带有 `#重点#` 标签的文档耗时多少？”。
5. **“离桌一刀切剥离，无法补录离桌学习行为”**
   - *问题现状*：检测到闲置直接从有效时长中剔除。但考研党经常“离桌背单词”、“在白板上演算推导”或“开半小时组会”；
   - *行业对标*：Timing (macOS) 在用户离桌返回时，会友好地询问“刚才是否进行了离桌活动”，允许快速归因为线下学习或直接丢弃。

#### 特性 4：离桌去水归因与时间轴手动微调补录 (AFK Reason & Timeline Manual Adjust)
- **业务价值**：解决“离开电脑去背书、线下研讨、纸质做题无法计入统计”的核心痛点，还原全天完整知识活动。
- **产品交互**：
  - **离桌唤醒归因气泡**：当检测到离开超过阈值（如 15 分钟）并重新激活电脑时，右下角轻量提示：*“检测到离开 25 分钟，这段时间是否在：[线下学习/阅读] [暂离休息] [丢弃]”*；若选择线下学习，自动保留该段时长并打上离桌标签；
  - **日历空隙点击补录**：在 24 小时时间轴上的空白时段，允许鼠标点击框选，手动补录一段“线下自习”或“纸质阅读”事件。

### 5.2 阶段二 (P1 - 中期护城河构建)：效能深度挖掘与生态下钻

#### 特性 1：产出效能联动——字数增量/编辑块数与速率量化 (Time-to-Output Analytics)
- **业务价值**：将时间统计升华为“生产力质量评估”，区分“深度沉浸产出”与“低效挂机翻阅”。
- **技术逻辑**：
  - 在切换文档或保存会话时，调用思源 API 查询当前文档的总字数（Word Count）与块数量（Block Count）；
  - 计算本次会话的**字数增量 $\Delta Words$** 与**修改块数 $\Delta Blocks$**；
  - 计算并展示文档**平均写作速率（WPM / Words Per Minute）**；
  - 在图表中提供“投入时长 vs 字数产出”双轴散点图，一眼识破哪些课题是“耗时长但进展慢的深水区”，辅助科研与写作破局。

#### 特性 2：多维聚合透视——笔记本分类、标签聚合与大纲下钻 (Multi-Level Drill-Down)
- **业务价值**：超越扁平的单文档限制，支持体系化的知识库视角。
- **产品设计**：
  - **笔记本视角 (By Notebook)**：按知识库/笔记本进行宏观汇总（如“2026考研”耗时 120h，“生活杂记”耗时 15h）；
  - **标签视角 (By Tags)**：提取文档内带有的 `#标签#`，按项目或专题汇总（如统计所有 `#数学二#` 的文档）；
  - **长文档大纲下钻 (By Headings)**：对于超过万字的超长论文或书稿，根据当前正在编辑的二级标题（H2 块），统计每个章节的耗时分布。

#### 特性 3：专注质量分与心流健康度模型 (Focus & Flow Quality Score - 借鉴 Rize)
- **业务价值**：告别单纯比拼“时长”的内卷，倡导科学健康的深度工作状态。
- **算法模型**：
  $$Score = 100 - (\text{频密切换惩罚系数} \times SwitchesPerHour) + (\text{单次长心流奖励系数} \times DeepSessionsRatio)$$
- **指标呈现**：
  - 看板呈现“今日专注健康分：88 分（心流充沛）”；
  - 针对频繁在 5~10 篇文档间无规律跳跃的用户，给出“精力碎片化预警”，提示用户固定主线任务。

#### 特性 4：多格式数据导出与通用日历双向订阅 (iCalendar / CSV / Shareable Cards)
- **业务价值**：破除数据孤岛，支持将专注轨迹同步到苹果日历、谷歌日历，以及生成社交打卡长图。
- **导出能力**：
  - **iCalendar (.ics)**：导出标准日程文件，也可提供本地 WebDAV / 本地订阅服务，让手机自带日历直接呈现思源专注时间块；
  - **CSV / Excel**：导出精细到秒级的明细日志，供自由职业者用于客户工时核算；
  - **一键生成精美长图海报 (Shareable Snapshot)**：生成类似 GitHub 风格的极简极客风成就打卡卡片，方便备考党打卡打卡圈。

### 5.3 阶段三 (P2 - 长期终极形态)：智能化协同与多维沉浸工作舱

#### 特性 1：沉浸禅模式 (Zen Mode) 与心流白噪音环境音 (Ambient Soundscape)
- **产品设想**：集成内置的轻量音频发生器（白噪音、林间雨声、图书馆翻书声、咖啡厅嗡鸣、432Hz 专注脑波音乐），并支持一键隐藏思源所有工具栏与侧边栏，进入极简全屏写作心流舱。

#### 特性 2：跨应用轻量桥接探索 (External Watcher Bridge)
- **产品设想**：通过轻量本地 WebSocket 或 HTTP 端点，与主流浏览器扩展或 ActivityWatch 进行可选联动。当用户在写思源时切到浏览器查阅相关技术文档，插件能感知到“当前正在阅读与思源关联的参考文献”，避免误判为断点，补齐跨应用学习闭环。

#### 特性 3：周期主动式 AI 效能教练与长期习惯年鉴 (Proactive AI Performance Coach)
- **产品设想**：由被动点击变为“周一早晨主动推送上周效能洞察”；结合整季度、整年度数据，挖掘用户的“高产星期几”、“疲劳周期规律”，并在岁末自动生成一本专属的《个人深度工作年度白皮书》。

## 6. 技术实现与架构落地指导

为了确保上述特性能够稳健落地，针对关键技术难点提供以下架构方案建议：

### 6.1 移动端适配与生命周期管理

移动端（iOS / Android）存在严格的后台挂起机制（App 进入后台后 JS 定时器会被休眠）。针对这一特性的设计规范如下：

```typescript
// 移动端挂起与前台唤醒生命周期守卫
export class MobileLifecycleGuard {
  private lastActiveTimestamp: number = Date.now();

  public init() {
    document.addEventListener("visibilitychange", () => {
      if (document.visibilityState === "hidden") {
        // App 切换到后台，立即结算当前 Session，防止后台被系统杀死导致数据丢失
        this.flushCurrentSession();
      } else if (document.visibilityState === "visible") {
        // 重新切回前台，校准时间戳并探测当前聚焦文档
        this.resumeTrackingAfterWakeup();
      }
    });
  }
  
  private flushCurrentSession() { /* 立即落盘存储 */ }
  private resumeTrackingAfterWakeup() { /* 重新初始化时间戳 */ }
}
```

### 6.2 高精度抗休眠计时与 Web Worker 机制

在开启主动番茄钟时，若用户在桌面端将思源最小化或长时间未激活窗口，浏览器的 `setInterval` 可能会被节流至每分钟一次，导致计时误差。
- **解决方案**：番茄钟核心倒计时不依赖累计递减计数器，统一基于**真实系统时间戳差值计算**：
  $$\text{RemainingSeconds} = \text{TargetTimestamp} - \text{Date.now()}$$
- 配合专用的 Web Worker 线程循环触发心跳，保证即使在思源最小化状态下，番茄结束提醒依然能够准秒触发。

### 6.3 思源内核 API 批处理与 Daily Note 注入机制

将统计数据写入思源 Daily Note 必须遵循低开销与防冲突原则：

```typescript
/**
 * 自动向指定 Daily Note 追加时间追踪摘要折叠块
 */
export async function appendSummaryToDailyNote(dailyDocId: string, markdownContent: string) {
  // 1. 构造标准思源折叠块 Markdown
  const foldBlockMd = `{{{row
{: custom-time-spent-log="true"}
### ⏱️ 源时记 · 今日专注轨迹摘要
${markdownContent}
}}}`;

  // 2. 调用思源内核 API 追加块 (appendBlock)
  const response = await fetch('/api/block/appendBlock', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      data: foldBlockMd,
      dataType: 'markdown',
      parentID: dailyDocId
    })
  });
  
  return await response.json();
}
```

## 7. 结语

“源时记（siyuan-time-spent）”从诞生之初，就精准踩在了现代知识工作者对**“免打扰、反虚假努力、重思源原生生态、重本地隐私”**的刚性诉求上。

通过本次与 Obsidian 社区插件、PC 桌面级顶级商业应用（Rize/Timing）以及移动端自律工具（Session/Forest）的横向对标，我们可以清晰地看到：
- **我们的长板极高**：在思源笔记内部，我们具备其他外挂软件永远无法比拟的**双向文档联动能力、一站式优雅看板与 AI 一键闭环沉淀机制**；
- **我们的短板明确且极具针对性**：通过在下一版本（v0.9.0）迅速补齐**“状态栏番茄钟双模引擎”、“移动端响应式支持”与“Daily Note 自动化沉淀”**，即可立竿见影地抹平与竞品的关键体验鸿沟；
- **我们的护城河空间巨大**：在中长期通过**“字数产出量化”与“多维层级透视”**，源时记将从单纯的时间记录器，真正演进成为思源生态乃至整个知识管理领域中最具影响力的**“深度工作效能大脑”**。
